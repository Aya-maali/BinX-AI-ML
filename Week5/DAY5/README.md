# Week 5 - Day 5

## What I Did Today

Today was the final day of Week 5, and it marked the transition from **Phase 2 (learning)** into **Phase 3 (the Capstone Project)**.

Instead of learning a new algorithm, today's work was about **choosing my capstone project, defining its scope, and planning the first sprint** before any actual project work begins.

I reviewed the six capstone project options provided by the program (Customer Churn Prediction, House Price Prediction, Sentiment Analysis, Image Classifier, Recommendation System, and Fraud Detection), and I selected:

> **Customer Churn Risk Prediction & Analysis**

I chose this project because it combines everything I learned across the first four weeks — classification, evaluation metrics, and preprocessing — with a clear, realistic business problem: predicting which customers are likely to leave a company before they actually do, and understanding why.

## What I Did for Project Planning

* **Selected the dataset:** the IBM Telco Customer Churn Dataset, a real dataset with 7,043 customers and 21 columns, including demographic info, subscribed services, contract/billing details, and a clear `Churn` target column.
* **Wrote the Problem Statement:** identifying customers likely to leave before they churn, and understanding why.
* **Defined the Project Objectives:** from EDA and preprocessing, to building and comparing models, to generating churn probability, risk levels, key risk factors, and retention recommendations.
* **Defined the Expected System Output:** for each customer — churn probability, risk level, prediction, main risk factors, and a recommended retention action.
* **Restated the Definition of Done** for the whole capstone (documented pipeline, trained model, deployed app, clean GitHub repo, technical write-up).
* **Planned Sprint 1** ("Data Understanding & Baseline"): built a full backlog of 9 tasks (dataset selection, data understanding, cleaning, EDA, preprocessing, baseline model, baseline evaluation, documentation, GitHub setup), each with a written acceptance criteria checklist.
* **Set up the GitHub repository structure** for the project (`data/`, `notebooks/`, `src/`, `models/`, `app.py`, `requirements.txt`, `README.md`) ready for Sprint 1 work to begin.

## What I Learned

Today I learned how to:

* Evaluate different project options against my own skills and interests before committing.
* Turn a general project idea into a clear problem statement and a measurable Definition of Done.
* Break a project down into a sprint backlog with concrete, checkable acceptance criteria instead of vague tasks.
* Judge whether a dataset is actually suitable for a given problem (clear target, relevant features, real-world source).
* Set up a clean project repository structure before writing any code, so the work that follows stays organized.

## Tools I Used

* Mentor consultation
* GitHub (repository structure + planned branch workflow)
* Jupyter Notebook (for documenting the project selection and Sprint 1 plan)
* Sprint backlog / acceptance criteria format

## Final Takeaway

Day 5 taught me that a good capstone project doesn't start with writing code — it starts with a clear problem, a suitable dataset, and an honest plan of what "done" looks like for the first sprint. No Phase 3 work begins until this plan is reviewed and approved by the mentor, which keeps the next four sprints focused instead of scattered.
